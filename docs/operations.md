# 이 PC의 최초 실행 상태

2026-11-10 화요일 KST에 이전 주제 파일을 교체하고 수집기를 시작했습니다.

- 기본 범위: 2호선, 매일 06:30~09:30·17:30~20:30, 30초 위치 수집.
- `.env`는 생성했으며 인증키 값은 비어 있습니다. **실제 운영 수집 건수는 최초 검증 시 0건**입니다.
- 백그라운드 프로세스는 실행을 확인했습니다. 최신 상태는 `status_background.cmd` 또는 `python collector.py --status`로 확인합니다.
- Windows 작업 스케줄러 등록은 현재 계정의 `Access is denied (0x80070005)`로 실패했습니다. 관리자 권한을 요청하지 않고 현재 사용자 시작프로그램의 `SSAFY-SeoulSubway-DailyCollector.lnk`를 등록했습니다.
- 로그인 시 수집기를 숨김 실행하고, 그 프로세스가 매일 수집 시간에 요청합니다. 로그인 상태·전원·인터넷 연결이 필요합니다. 수동 중지 후에는 직접 시작하거나 다시 로그인해야 합니다.
- 시작프로그램 해제: `powershell -File scripts/register_schedule.ps1 -Remove`. 해제와 현재 프로세스 중지는 별개입니다.

## 실제 수집으로 전환

1. `.env`에 `SEOUL_SUBWAY_API_KEY`를 넣습니다. 실행 중이면 최대 다음 위치 주기(약 30초) 안에 다시 읽습니다.
2. `--status`에서 `keys_configured`뿐 아니라 `positions` 증가와 `last_position` 갱신을 확인합니다.
3. 공공데이터포털 키와 두 API 활용승인을 추가하면 시간표·공지 수집이 시작됩니다. `delay_matching`으로 실제 매칭 여부를 확인합니다.
4. SK 키를 추가하면 지원 역 목록과 오늘의 **요일에 해당하는 과거 통계**를 받습니다. 실시간 칸별 혼잡도가 생기는 것은 아닙니다.

첫날 실행 전 시간은 복원되지 않습니다. 특히 17:30부터 최초 정상 응답까지는 관측 공백입니다. PC 초기화 전 `python scripts/backup.py`로 만들고 다른 저장장치로 옮겨야 데이터와 인증키를 보존할 수 있습니다.

## 2026-11-11 인증키 연결 확인

10시대에 실제 인증키로 위치·시간표·공지·SK 역 목록·열차 통계·칸 통계 API의 HTTP 200 응답을 확인했습니다. SK 역 목록의 선택 인자 오류를 수정하고 백그라운드 프로세스를 재시작했습니다. 세 키 모두 읽히며 다음 정규 수집 시작은 2026-11-11 17:30 KST입니다.

진단 호출은 `probe_` 데이터셋으로 원본·요청 이력에 보관했고 정규 출퇴근 관측 테이블에는 넣지 않았습니다. SK 실제 응답은 임시 DB에서 열차 통계 108행·칸 통계 1,080행으로 정규화까지 확인했습니다. 최종 연결 결과는 로컬 `data/credential_check.json`에서 확인할 수 있습니다. 날짜별 정규 수집 0건과 진단 호출 성공은 별개입니다.

## 2026-11-11 수집 범위 변경

열린데이터광장 활용사례 등록 승인으로 위치 수집을 1~8호선으로 넓혔습니다. 운행 공지는 설정에서 끄고(코드·기존 데이터 보존) SK 혼잡도 수집 코드는 제거했으며(기존 행은 DB에 보존), 도착정보 샘플·승하차 인원 수집과 정적 CSV 적재(`--load-reference`)를 추가했습니다. 2호선 시간표의 내선·외선 방향 코드가 위치 API와 반대로 저장되던 문제를 고쳤고, 기존 행은 수집기 시작 시 자동 보정됩니다.

적용 후 확인할 것:

1. `.env`에 `SEOUL_OPEN_API_KEY`(열린데이터광장 일반 인증키)를 넣습니다. 비워두면 승하차 수집만 건너뜁니다.
2. `--status`의 `last_position`에 8개 노선이 모두 갱신되는지, `rows.arrival_samples`가 늘어나는지 확인합니다.
3. 하루 1,000건을 넘긴 뒤 `seoul_subway_quota.verdict`가 `lifted_confirmed`인지 확인합니다. `limit_hit`이면 `lines`를 `["2호선"]`으로 되돌립니다.
4. `delay_matching`을 노선별로 보고, `direction_mismatch`가 많으면 방향 대응표를 다시 확인합니다.

### 위치 호출 간격 15초

2026-11-11 낮에 `scripts/check_interval.py`로 2호선을 5초 간격 3분(36건) 측정했습니다. 관측 열차 40대, 원천 값 변화 112회, 같은 열차의 값이 바뀌는 간격은 중앙값 40초였고 그중 48%(36/75)가 30초 안에 연달아 바뀌었습니다. 30초 호출로는 역 도착 순간을 놓치는 경우가 많아 15초로 줄였습니다(하루 위치 호출 11,520건, 예산 14,000건).
