# 실제 시간표와 실시간 정보로 계산하는 로컬 초안

2026-11-17 구현. 입력과 출발·도착 시각은 승강장 기준이다. 특정 통근 경로를 하드코딩하지 않는다.

## 계산

1. 공식 시간표를 운행일·열차번호·방향·기종점·지선·유효기간별로 정리한다. 임시 시간표와 자정 이후 24~29시 표기를 처리한다. 급행은 원천에 정차 시각이 있는 역에서만 승하차한다.
2. EC2 기존 키로 현재 도착정보를 조회한다. 원천 생성 시각 + 남은 초를 사용하며, 지금 시각에 남은 초를 다시 더하지 않는다. 0초·오래된 응답·모호한 열차 식별은 예측 앵커로 사용하지 않는다.
3. 노선·열차번호·방향·행선지·운행 발생 시각으로 유일하게 연결된 열차만 보정한다. GTX-A의 숫자 ETA가 없는 경우에는 신선한 위치 응답의 도착/출발 상태를 별도로 사용한다. 현재 추정 지연을 후속 시각에 유지하는 초기 방식이며 학습 모델이 아니다. 지연을 매 정거장마다 누적해서 더하지 않는다.
4. 실제 운행 열차를 탑승 횟수별로 훑어 빠른 도착을 탐색한다. 목표시각에서 역방향으로 늦은 출발과 도착 여유를 반영한 출발을 탐색한다. 기본 최대 환승은 3회이며 최대 4회로 변경 가능하다. 상태별 노선 조합 3개와 열차별 탑승 이력을 제한하므로 전역 최적성을 주장하지 않는다.
5. 공식 환승 최단 이동시간 + 사용자 추가 여유 + 승차 여유 30초로 환승을 판단한다. 반대 방향 값 적용은 추정으로 표시하며, 미확보 구간의 기본 가정과 사용자 직접 입력을 구분한다. 공식 CSV는 실제로 MM:SS 형식이며 분기·혼잡·승강장 동선 실측이 아니다.
6. 앞의 0·1·2대를 보내는 사용자 시나리오를 적용할 수 있다. 고정 배차시간을 더하지 않고 같은 방향의 다음 실제 운행 열차를 사용한다. 실시간 승강장 혼잡도나 검증된 탑승 실패 예측 모델은 아니다.

## 확보한 실제 자료

- EC2에서 2026-11-17 당일 시간표 202,008행을 로컬 압축 캐시로 가져왔다. 기본 1~8호선 145,737행에 나머지 노선 자료를 추가했다.
- 원천 API는 `https://apis.data.go.kr/B553766/schedule/getTrainSch`, [공식 설명](https://www.data.go.kr/data/15143847/openapi.do). `lineNm`은 포함 검색이다. 경의중앙선은 `경의`, 우이신설선은 `우이`로 조회하고 원문을 보존하면서 서비스 노선명에 대응했다.
- 19개 노선의 시간표가 있으나 **9호선의 현재 유효한 원천 응답은 38개 지도 역 중 16개 역만 포함한다.** 누락 운행을 합성하지 않으며 결과에 부분 범위를 표시한다. 2026-11-16 시간표 변경과 관련한 추가 확인이 필요하다.
- 공식 환승 CSV 145행: [환승역거리 소요시간](https://www.data.go.kr/data/15044419/fileData.do). 서울역 4호선→GTX-A 3분40초는 최단거리 환산값이며 GTX-A→4호선 적용은 역방향 추정이다. 환승의 방향·동선에 따라 사용자 보정이 필요하다.
- 보조 연구용 코레일 파일과 출처는 `services/web/import_sources/SOURCES.md`에 있다. 현재 계산은 실제 API 시간표를 사용하며, 내려받은 XLSX를 임의로 엮어 운행 열차를 만들지 않는다.

## 운용과 한계

- 웹과 계산은 로컬 PC에서 실행한다. 인증키는 EC2 메모리에만 존재하며 브라우저·로컬 캐시에 복사하지 않는다.
- 실시간 요청은 EC2의 기존 `requests`·원문 gzip·일일 호출 예산을 사용한다. 모든 로컬 사용자가 25초 캐시를 공유한다. 기존 수집기는 평일 출퇴근 시간 수집을 계속 유지한다.
- 화면을 보고 있을 때 30초마다 재계산하며 순위·열차 조합을 다시 표시한다. 아직 탑승 완료 상태나 알림 발송 기능은 없다.
- 현재 위치 지도는 수집기의 최근 저장 관측이다. 시간대 밖 오래된 위치는 흐리게 표시하며, 경로 계산용 현재 도착예정 조회와 구분한다.
- 다음 날은 해당 요일·유효기간의 시간표를 사용한다. 현재 관측을 다음 날 열차에 적용하지 않는다. 공휴일은 수집기 `day_type_overrides`를 공유하며 별도 법정공휴일 API는 미연결이다.
- 단절된 시간표·미관측·API 장애는 시간표 기준 또는 데이터 부족으로 표시한다. 실제 탑승 및 도착을 보장하지 않는다.
- 시간표 캐시는 `data/`이므로 Git에 포함하지 않는다. 새 PC에서는 실행 안내의 동기화 절차를 먼저 수행한다. 시간표 변경·새 운행일 자료를 확보한 후 캐시 갱신과 서버 재시작이 필요하다.

## 확인

웹 엔진 테스트는 실제 시간표 기반 비교, 환승 불가능 시 다음 열차 선택, 생성 시각 보정, 지연 중복 가산 방지, 급행 무정차, 혼잡 대기 시나리오, GTX-A 위치 앵커, 자정·만료·순환 구간을 검증한다. 가상 데이터는 테스트 파일에만 있다. 브라우저에서는 여러 경로·정렬 탭·실시간 갱신·모바일 배치를 확인한다.
