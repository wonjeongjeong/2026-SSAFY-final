# 실시간 수집 범위 확장 — 2026-11-16

현재 서울시 실시간 API에서 실제 인증 응답을 확인한 19개 노선을 수집 대상으로 사용합니다. 1~8호선 제한은 기존 프로젝트의 범위 결정이었으며 공개 API의 제공 범위를 뜻하지 않습니다.

2026-11-16 16:34~16:40 KST 검증: 추가 11개 노선 모두 위치 API에서 운행 열차가 응답했습니다. 9호선 첫 확인은 32대 중 급행 12대, 경의중앙선은 24대 중 급행 1대였습니다. 도착정보 일괄 응답은 3,021행으로 19개 노선, 일반·급행·ITX를 포함했습니다. 시각·운행 상황에 따라 개수는 달라집니다. 요청은 기존 `requests`와 원본 아카이브에 `coverage_probe`로 기록했습니다.

위치 API의 `ALL` 노선 요청은 빈 응답이었으므로 전체 위치가 들어온다고 가정하지 않습니다. 노선별로 요청합니다. 도착정보는 공식 `realtimeStationArrival/ALL` 일괄 서비스를 사용합니다.

수집 설정:

- 평일 06:30~09:30, 17:30~20:30 KST를 유지합니다.
- 위치: 19개 노선 각각 목표 15초 간격, 노선별 시차 호출, 최대 4개 요청 병행.
- 도착정보 이력: 별도 실행 경로에서 120초 간격으로 일괄 응답을 정규화합니다. 웹은 조회 중 15초 캐시로 최신 정보를 공유하며, 웹 응답은 최신 파일로 교체합니다.
- 위치 27,360회 + 도착 샘플 180회 = 하루 기본 27,540회. 재시도·추가 웹 조회와 공유하는 로컬 상한은 35,000회입니다.
- 지연 계산은 별도 프로세스에서 새 관측을 증분 처리하며 CSV는 수집 시간 밖에서 생성합니다. API 응답 지연이나 서버 부하가 있으면 실제 호출 간격은 길어질 수 있습니다.
- 기존 인증키는 하루 1,000회 초과 성공 이력이 있고 한도 해제 상태를 확인한 상태입니다. 다른 인증키로 옮길 때도 같은 한도를 가정하지 마세요.

정규화 컬럼:

- `positions.express_code`: 원천 `directAt` 원문 코드. 0=일반, 1=급행, 7=특급. 미제공은 NULL, 알 수 없는 코드는 원문 그대로 보존합니다.
- `positions.train_type`: 위 코드에 대한 일반/급행/특급. 알 수 없으면 NULL입니다.
- `arrival_samples.train_type`: 원천 `btrainSttus`. 일반·급행·특급·ITX 등 제공 문자열을 보존합니다.
- `arrival_samples.eta_seconds`: 원천 `barvlDt`. 숫자로 해석할 수 없으면 NULL입니다. 0이라는 이유만으로 실제 도착을 확정하지 않습니다.
- 전체 원천 행은 기존 `payload_json`과 gzip 아카이브에 그대로 보존합니다.

기존 DB는 컬럼을 추가하는 방식으로 마이그레이션합니다. 과거 행을 자동으로 다시 쓰지 않으므로, 과거 데이터의 새 컬럼은 NULL일 수 있습니다. 과거 원문에 필드가 있으면 SQL의 JSON 함수로 확인하거나 별도 재처리를 할 수 있습니다.

중요한 구분:

1. 실시간 위치·도착정보를 받는 것과 시간표 대비 지연을 계산하는 것은 별개입니다. 현재 연결한 서울교통공사 시간표 API는 1~8호선에만 사용하며, 신규 노선에 무작정 같은 시간표 요청을 보내지 않습니다.
   코레일 경의중앙선·경춘선·서해선·수인분당선·경강선은 `--load-timetable`로 공식 XLSX를 적재하면 지연 매칭에 사용합니다. 날짜별 시행본과 평일/휴일을 선택하며, 당일 증분 계산도 시간표 변경을 감지해 기존 관측을 재계산합니다.
2. 급행을 표시하는 필드만으로 급행 경로 계산이 완성되지는 않습니다. 급행 정차역·시간표·종착역·운행 계통을 확보해 일반 열차와 따로 경로를 구성해야 합니다.
3. 위치는 역·진입/도착/출발 상태입니다. 앱의 역 사이 움직임은 보간 표현일 수 있으며 GPS 실측으로 단정하지 않습니다.
4. 이 19개 노선이 전국 또는 수도권의 모든 노선이라는 뜻은 아닙니다. 인천 1·2호선, 김포골드라인 등은 이번 일괄 응답에 없었으며 별도 공식 소스를 검증해야 합니다.
5. 2026-11-17 로컬 웹을 19개 노선 지도·역 검색으로 확장했습니다. 기존 SSH 연결로 EC2의 최근 원본 위치 관측과 어제 퇴근·오늘 출근 시간대 수신 건수를 읽어 표시합니다. 열차 위치·일반/급행 표시는 실제 관측이며, 출발 추천은 여전히 예시 시간표입니다. 급행 정차 패턴·학습 기반 지연 예측은 미구현입니다.
