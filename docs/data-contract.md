# 현재 저장 계약

모든 시간은 `+09:00` KST입니다. 미확보 값은 SQL NULL입니다. 수집 시각과 원천 시각은 서로 다릅니다. SQLite 원본 스키마는 `sql/schema.sql`입니다.

| 테이블 | 주요 내용 |
|---|---|
| positions | 날짜·요일·출퇴근 구분, 수집/원천 시각, 호선·열차번호·역·방향·상태, 원문 행, 품질 |
| arrivals | 도착 상태 최초 관측, 직전 관측 시각, 불확실성 구간, 위치 이벤트 ID |
| timetable | 당일 내려받은 유효 시간표 행. 열차·역·방향·요일 유형·출도착 시각 |
| delays | 도착 관측과 시간표 매칭, 지연 구간 상·하한 또는 미매칭 이유 |
| congestion | 이전 SK 통계 (2026-11-11 수집 코드 제거, 기존 행만 보존, CSV 내보내기 제외) |
| notices | 공지 발생/수집 시각, 대상 호선·역, 제목·본문 (2026-11-11 수집 중단, 기존 행 보존) |
| arrival_samples | 도착정보(일괄) 샘플. 1~8호선만. 열차번호(`btrainNo`)·역·방향·`arvlCd`·원천 시각. 위치 기반 도착 검증용이며 지연 정답이 아님 |
| boarding_volume | 승하차 인원 원본 행과 사용월(`use_month`). 컬럼은 원천 그대로 `payload_json`에 보존 |
| reference_files | 직접 적재한 CSV의 sha256·데이터셋·파일명·인코딩·컬럼·행 수. 같은 파일은 다시 적재하지 않음 |
| reference_rows | CSV 원본 행(`dataset`, `row_no`, `payload_json`). 컬럼 이름을 바꾸지 않음 |
| requests | HTTP 시도별 공급자·대상·결과·응답 원본 위치. 일일 예산은 이 행 수로 집계 |
| gaps | 시작 이전·미관측·요청 실패·불완전 페이지 가능 구간 |
| checkpoints | 시간표·통계 수집 진행과 열차별 마지막 처리 상태 |

## 식별과 복구

위치 이벤트 ID는 날짜·노선·원천 행의 SHA-256입니다. 같은 응답 반복 수신은 중복 적재하지 않습니다. 서로 다른 원천 시각의 동일 역·상태는 별도 관측으로 남깁니다. 도착 이벤트는 최초 도착 관측에 연결하며 같은 역 도착 상태를 반복 수신해도 도착 횟수를 늘리지 않습니다. 궤적 체크포인트와 위치·도착 행을 같은 트랜잭션으로 기록합니다.

요청 시도는 네트워크 전 커밋합니다. 재시도와 중단된 요청도 호출 예산을 사용한 것으로 계산합니다. 정상 응답 원문은 정규화 전 저장합니다. 원본과 정규화 데이터 사이에서 종료되면 원본으로 복구할 수 있습니다. 시간표·통계는 성공 단위 체크포인트를 쓰므로 완료 페이지를 반복해서 요청하지 않습니다.

## 도착과 지연 품질

- `fresh`: 원천 시각이 수집 시각 대비 -5~90초 이내. 이 한계는 설정으로 바꿀 수 있습니다.
- `stale_or_missing_time`: 원천 시각이 없거나 오래됨/미래 시각. 위치 원문만 저장하고 도착 정답으로 쓰지 않음.
- `bounded_observation`: 직전 원천 관측 후 도착 상태로 바뀌었고 간격이 90초 이내. 도착은 `(lower_bound_at, observed_at]` 구간의 관측 추정.
- `left_censored`: 처음 봤을 때 이미 도착해 있거나 직전 관측과 간격이 큼. 지연 정답을 만들지 않음.

`delay_seconds`는 도착 관측 시각으로 계산한 상한이고 `lower_delay_seconds`는 직전 관측으로 계산한 하한입니다. 음수는 조착 가능 관측값이므로 임의로 0으로 자르지 않습니다. 원천 전파 지연이 있을 수 있어 실제 도착의 엄밀한 센서 오차 구간을 보장하지 않습니다.

열차는 먼저 정확한 번호로 짝짓고, 위치 원문의 종착역(`statnTnm`)과 시간표 종착역(`arvlStnNm`)이 둘 다 있으면 같아야 합니다. 정확한 번호가 없을 때만 코레일 K 표기(`3257K`, `K4626`, `0473`→`K473`), 2호선 앞자리 차이(`3308`→`2308`), 종점 회차 뒤 연계 번호(시간표 `lnkgTrainno`)를 보며, 이때는 종착역이 반드시 같고 시간표와 20분 이내여야 합니다. 20분 넘게 차이 나면 같은 번호의 다른 회차(예: 매시간 다니는 1호선 급행)일 수 있어 `unverified_large_delay`로 남기고 지연을 확정하지 않습니다. 시각이 가깝다는 이유만으로는 짝짓지 않습니다(출퇴근 배차 2~3분이라 뒤차와 짝지어지면 지연이 틀어짐). 방법은 `delays.match_method`(`exact`·`korail_k_number`·`line2_first_digit`·`linked_trainno`)에 남습니다.

`unmatched_timetable`, `ambiguous_timetable`, `direction_mismatch`, `destination_mismatch`, `unverified_large_delay`, `unbounded_arrival`의 지연 값은 NULL입니다. `destination_mismatch`는 같은 번호·역·방향의 시간표가 있지만 종착역이 달라 다른 회차로 보이는 경우입니다. `direction_mismatch`는 열차번호·역은 맞는데 방향 코드만 다른 경우로, 방향 대응표 점검 신호입니다. 매칭 기준은 당일·호선·정확한 열차번호·역명·방향이고(역명은 위치 API 표기를 그 날 시간표 표기로 맞춘 뒤 비교: 괄호 부기 제거와 `config.STATION_ALIASES`의 확인된 별칭, 시간표에 실제로 있는 이름만 인정. `delays.station_name`은 맞춘 뒤의 시간표 표기), 관측 시각과 1시간 이내의 유일한 시간표만 후보입니다. 보수적인 초기 규칙이므로 1시간 이상 대규모 지연은 매칭되지 않으므로 원본 위치 궤적으로 따로 확인합니다(운행 공지는 2026-11-11부터 수집하지 않음).

## 혼잡 통계 계약

2026-11-11부터 열차 혼잡도는 서울교통공사 지하철혼잡도정보(`reference_rows`, `dataset='train_congestion'`)를 씁니다. 정원 대비 탑승 비율(%)의 30분 단위 과거 평균이며, 탑승 실패 대기는 이 값에 기준치를 적용한 **가정 기반 시나리오**로 표시합니다. 아래는 이전 SK 데이터(`congestion` 테이블)의 계약입니다.


`car_no IS NULL`은 열차 전체 통계, 1 이상은 칸별 통계입니다. `measurement_kind`는 반드시 `historical_statistic`입니다. `fetched_date`는 다운로드 날짜, `dow`는 원천 통계 요일, `stat_start_date`/`stat_end_date`는 집계 기간입니다. `train_no`를 만들어 붙이지 않습니다. 운행 조합은 이전역·시작역·종착역·방향으로 보존하고 향후 실시간 열차에 매핑하면 **통계 기반 추정**으로 표시합니다.

## 후속 Kafka 이벤트

다음 단계에서 원문 아카이브를 재생할 때 `schema_version`, `event_id`, `source`, `measurement_kind`, `source_timestamp`, `collected_at`, `date_kst`, `dow`, `payload`를 공통 봉투로 사용합니다. 현 단계에 Kafka 전송·exactly-once 보장은 구현되어 있지 않습니다.
